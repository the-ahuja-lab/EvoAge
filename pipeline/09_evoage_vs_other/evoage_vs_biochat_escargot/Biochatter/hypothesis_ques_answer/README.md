# Testing hypotheses with BioChatter on the EvoAge KG

Running 101 published biological hypotheses through BioChatter, against the
EvoAge knowledge graph, to see what evidence it can retrieve for each.

## What we did, step by step

1. **Took the hypotheses.** 101 statements from `Hypothesis_Questions_to_answer.csv`,
   column `Right Hypothesis`. Each comes from a real 2025 paper (Title, Journal,
   DOI kept alongside).

2. **Gave BioChatter our graph.** BioChatter ships no data of its own — it only
   writes queries. We described the EvoAge graph in `../schema_info.yaml`
   (16 node types, 89 relationship types), generated by reading the live Neo4j.

3. **Sent each hypothesis in as a question.** BioChatter picks the relevant
   entity types and relationships, writes a Cypher query, and runs it against
   the EvoAge Neo4j (`neo4j://192.168.3.153:3333`) — the same graph EvoAge uses.

4. **Recorded what came back.** For every row: the Cypher it wrote, how many
   rows the graph returned, the answer it phrased, how long it took, and any error.

5. **Asked the model to summarise strictly.** The answer step is told to use
   *only* the retrieved rows and to say plainly when nothing was found — so it
   does not fill gaps from its own training knowledge.

## How the KG is used

```
Hypothesis (plain English)
        ↓
BioChatter reads schema_info.yaml  (what nodes/relationships exist)
        ↓
BioChatter writes a Cypher query
        ↓
Query runs on the EvoAge Neo4j     (45.5M nodes, 1.24B relationships)
        ↓
Rows returned  →  LLM phrases an answer from those rows only
```

Nothing in the EvoAge system is modified. This is read-only.

## How to run it

```bash
conda activate biochatter
cd /storage/Arushi/090526_EvoAge/kg_formation/hypothesis_testing/EVOAGE_VS_OTHERS/Biochatter/hypothesis_ques_answer

python run_hypothesis_benchmark.py                    # all 101 rows (~20 min)
python run_hypothesis_benchmark.py --limit 5          # quick test
python run_hypothesis_benchmark.py --resume           # continue if interrupted
python run_hypothesis_benchmark.py --column "Inverse Hypothesis"
```

Model: **deepseek-v4-flash** — the same model used for the 37-question benchmark
and for Escargot, so the framework is the only thing that differs.

Results are saved after every row, so progress can be watched while it runs.

## How to read the results

- **`n_rows` > 0** — the graph had something relevant; check whether the returned
  entities actually match the hypothesis.
- **`n_rows` = 0** — the graph had no matching edge. This is the *expected* result
  for a genuinely novel hypothesis, not a crash.
- **`cypher`** — worth reading even when rows are 0. It shows whether BioChatter
  understood the hypothesis correctly, which is separate from whether the graph
  could answer it.

## The important caveat

**BioChatter can only find what is already in the graph.** It has no embedding
model and no scoring, so it cannot judge a relationship that is not present — it
simply returns nothing.

A hypothesis worth testing is usually about a link that is *not yet* in the KG.
So "no evidence found" is BioChatter working as designed, not failing.

Example, verified: the betaine hypothesis claims betaine inhibits TBK1. In the
EvoAge graph, betaine exists (as *glycine betaine*) and TBK1 exists, but there is
**no edge between them in either direction**. BioChatter returns 0 rows and says
there is no supporting evidence. It cannot say whether the claim is plausible.

This is the contrast with EvoAge, which scores absent triples with RotatE/RESCAL
and returns an accept/reject verdict with a confidence — so a large number of
0-row results here is a meaningful finding about retrieval-based tools, not a
broken run.

## One thing to watch

If an answer states confident biological detail while `n_rows = 0`, that content
came from the language model's own training data, not from the EvoAge graph.
Always check `n_rows` before trusting an answer.
